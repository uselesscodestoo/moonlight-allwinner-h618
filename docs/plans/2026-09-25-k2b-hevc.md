# K2B HEVC experiment

Work only on branch k2b-hevc, based on validated 6bdfe09. Keep the stable AVC
checkout and its runtime untouched. Target actual hardware decode and display
of 1920x1080 60 fps, HEVC Main 8-bit SDR, NV12 DMA-BUF into DE33.
No software decode fallback, HDR, Main10, scaling, or higher frame-rate work.

## Design and execution

1. Reuse the pinned CedarC archive's aarch64 libawh265.so. Add its SHA256 to
   the private runtime manifest and register CreateH265Decoder with the
   existing VDecoderRegister API, alongside H.264.
2. Accept VPS fragments and select the negotiated H.264/H.265 hardware codec.
   Preserve queue limits, predecode scheduling, fences, recovery, audio, and
   managed desktop restoration. Keep H.264 as launcher default.
3. First extend focused loader/AU/codec-selection tests and observe failures;
   implement the minimal changes and rerun those tests on the board.
4. Build a separate native runtime. Extend production-object sample replay to
   HEVC. Generate a fixed 600-frame 1080p60 Main sample on the PC, replay on the
   board, inspect actual output format, display cadence, hashes and cleanup.
5. Regress AVC, then request HEVC explicitly for a bounded Sunshine session.
   Require screen confirmation; plugin loading alone is not decode acceptance.

## Initial evidence

Both worktrees start at 6bdfe09. Board baseline frame/AU/queue tests pass.
The pinned libawh265.so exports CreateH265Decoder and resolves dependencies
against the existing private runtime. Hardware HEVC remains unproven.
