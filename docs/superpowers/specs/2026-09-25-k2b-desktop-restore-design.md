# K2B 串流退出后的 XFCE 恢复设计

## 目标与已验证事实

保留现有 `sudo sh tools/k2b-stream.sh HOST [options]` 使用方式。由 systemd
托管每次串流，在串流退出后调用独立恢复脚本，不修改 Moonlight 的解码或显示代码。
不设置开机串流，不自动重连，不改变网络、音频路由或 H.264/1080p60 参数。
HEVC 接入不属于本次改动。

实测确认：退出串流后 Xorg、XFCE 会话仍存活。厂商内核启用了
`CONFIG_DISP2_SUNXI_DEVICE_OFF_ON_RELEASE`，最后一次关闭 `/dev/disp` 会关闭
输出。通过 debugfs 对 disp0 执行 `blank 0`，再通过 fb0 的
`FBIOBLANK(FB_BLANK_UNBLANK)`，已恢复原桌面，用户确认键鼠和桌面正常。
恢复后的 HDMI 为 1080p60 RGB，Xorg 和 XFCE 进程没有重启。

## 方案与替代方案

采用 systemd 服务的 `ExecStopPost` 调用恢复脚本。板端 systemd 249 的本地
文档确认此入口覆盖服务正常退出、异常退出及启动失败后的清理。

仅使用父 shell 的 `trap` 更简单，但父 shell 被强杀时无法兜底，因此不作为
恢复责任主体。恢复操作也不放进 Moonlight 的信号处理函数，以免依赖已崩溃进程。

## 启动与停止

- 启动脚本创建单实例、按需运行的 systemd 串流服务，保留 host 和额外参数。
- 显式传递现用 Pulse 音频连接信息，不依赖 systemd 自动继承 sudo 环境。
- 服务使用现有私有 Cedar 运行库、配对目录和输入设备；日志保持可查看。
- 保留 Ctrl+C 停止方式：启动入口收到退出信号时请求 systemd 正常停止服务。
  启动终端意外消失不能取消 systemd 的后处理责任。
- 不设置自动重启。停止首先使用正常终止信号；禁用超时后的自动 SIGKILL，
  避免为恢复桌面而强杀仍可能持有 VPU/DMA 资源的进程。
- 同时只允许一个托管会话；新启动不得与上一轮停止或桌面恢复重叠。

## 独立恢复入口

提供可手动执行的恢复脚本，同时用作 `ExecStopPost`。所需 fb0 小工具放在
Moonlight 项目内构建，不长期依赖探针目录中的现成可执行文件。

恢复前确认没有仍在运行的 Moonlight 或其他 `/dev/disp` 使用者；有占用时拒绝
接管并报告原因。然后执行已验证的两个步骤：启用现有输出、恢复桌面图层。
不改变显示模式，不重启 XFCE，不常驻持有 `/dev/disp`。

恢复失败须记录具体步骤并返回失败，不把“后处理运行过”当作“桌面恢复成功”。
重复执行应保持现有桌面可用。服务结果与恢复结果均应能从日志辨认。

## 保障边界

systemd 正常工作且服务已结束时，不依赖 Moonlight 自身来调用后处理。
掉电、内核或驱动卡死、未退出的不可中断进程不在无条件恢复保证内。
应用被 SIGKILL 后可以调度后处理，但不能保证厂商硬件状态仍可恢复；不得
通过强制复位、释放不明 DMA 资源或反复尝试掩盖失败。

## 验证与交付

1. 用不访问 VPU/显示设备的替身程序测试正常退出、非零退出、信号退出、
   SIGKILL、启动失败，以及启动端消失后独立后处理仍可执行。
2. 测试参数及音频环境传递、单实例保护和手动恢复入口。
3. 使用真实 AVC 串流验证正常退出、Ctrl+C 和重复启动后的桌面恢复；
   不对工作中的 VPU 做强杀实验。由用户确认原桌面和输入可用。
4. 保持当前已验证的解码程序可回退；同步本地与板端脚本、工具和使用说明。

用户已认可 systemd 托管加独立恢复脚本的方向。本文件待用户确认后进入实现。
