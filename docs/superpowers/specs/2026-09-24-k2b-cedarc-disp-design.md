# KICKPI K2B 厂商内核 Moonlight 独立后端设计

日期：2026-09-24。状态：总体方案及本文均已获用户确认通过。

## 目标与边界

在 KICKPI K2B / H618 / 厂商 Longan Linux 5.4.125 上，实际硬件解码并
通过 HDMI 显示 1920×1080、60 fps 的 Moonlight 串流。建立独立维护的
`k2b-cedarc-disp` 分支，不提交上游 PR，不擅自推送远程。

以 `h618-egl-download` 的 `4e870a2` 为起点，保留原有 Orange Pi 后端。
本地工作树：`F:/temp/moonlight-embedded/.worktrees/k2b-cedarc-disp`。
板端目标：`/home/kickpi/projects/moonlight-embedded`。
已有 `cedarx_test` 和 `disp_test` 保留为独立参考与回归基线，不覆盖它们。

这不是仅创建分支、仅能编译或仅完成解码的任务。静态彩条、HDMI 60 Hz、
解码吞吐大于 60 fps、每秒提交 60 次，都不能单独证明目标完成。
不以降低分辨率、软件解码、CPU 像素复制或 RGB 转换作为达标替代方案。

首个达标路径采用已验证的 H.264 / NV12；HEVC、HDR、120 fps、其他板型
不是本次验收前提。保留 Moonlight 的正常音频、输入、配对和连接功能。
停止后恢复厂商桌面不是本次验收条件，这是用户已明确接受的限制。

## 路线选择

1. **采用：新增显式选择的 `k2b` 后端。** 复用固定版本 CedarC、已有 CMA
   导出器和厂商 disp 接口。不依赖 Mali、EGL、X11 或主线 Cedrus。
2. 不采用：改写或替换现有 X11/VAAPI 后端。它服务另一块板卡和驱动栈，
   混在一起会增加回归风险，且 K2B 当前没有可用的硬件 OpenGL 路径。
3. 不采用：先更换内核或系统。当前两个独立探针已证明有价值的能力，
   先验证它们的直连；若最终必须修改厂商显示内核，另行提出明确范围。

## 已知证据与不可外推部分

- 解码探针输出 NV12：存储尺寸 1920×1088、步长 1920、有效裁剪
  1920×1080。600 帧有效像素哈希与软件参考逐帧相同，且互不相同。
- 不读回像素的解码吞吐约 182 fps；这不包含显示，也不保证每次解码
  调用小于 16.67 ms。哈希验证约 46.7 fps 包含 CPU 同步及读取开销。
- 静态 NV12 DMA-BUF 彩条已获得用户目视确认，不能据此确认动态帧回收。
- CMA 配置为 128 MiB；当前导出器单分配上限 32 MiB、总额 96 MiB。
- `FBIO_WAITFORVSYNC` 的等待代码被注释。`DISP_LAYER_GET_FRAME_ID`
  虽存在于头文件，已检查的显示实现没有对应 ioctl 分支。
- `/dev/disp` 的 poll 和时间戳接口可提供刷新事件，但事件也可能发生在
  寄存器同步被跳过时。它不是逐缓冲区完成通知。
- SET_CONFIG2 导入失败可禁用图层后仍返回成功；配置读回是必要检查，
  但其本身仍只是软件状态，不能证明已经扫描输出。
- 用户确认目标 IP 为 `10.33.184.81`。最近只读检查可登录、无测试进程，
  但启动 ID 未改变，不能据此宣称已定位此前死机原因。

源码依据位于厂商树的 `drivers/video/fbdev/sunxi/disp2/disp/`：
`dev_fb.c`、`dev_disp.c`、`de/disp_manager.c`、`de/disp_private.c`、
`de/disp_display.c`；VPU 依据为 `drivers/media/cedar-ve/cedar_ve.c`。

## 组件与数据流

`Moonlight H.264 完整帧 → CedarC 压缩码流缓冲 → VPU NV12 DMA-BUF
→ disp 图层导入 → DE → HDMI`。

### Moonlight 适配层

通过独立 CMake 开关启用，显式 `-platform k2b` 选择；不改变旧后端默认
行为。平台注册、视频回调和能力声明保持与现有框架一致。
未验证的编码、位深、分辨率或格式明确拒绝，不静默回退软件路径。
复用原有网络、音频和 evdev 输入实现。

网络回调、解码工作和显示等待通过有界队列解耦。队列满或解码失步时
记录丢帧/请求关键帧，不无限堆积延迟。CedarC 实例由受控线程访问，
避免依赖其未证明的并发安全性。具体队列容量由可用帧池及持有测试确定，
必须有显式上限与队列统计。

### CedarC 与内存层

固定复用已验证的运行库提交
`243f2cbe84a817344d2502f4dd3d66b81338282f` 的
`library/aarch64-none-linux-gnu`，使用 `TINA_LINUX_SUPPORT=0` 的配套 ABI。
归档 SHA256 为
`ee32abb0100b6763b11d7db61d69865c43adeff07acc2be99b28edd95b85ed04`。
记录依赖来源、哈希及许可证边界，不混用其他工具链目录的二进制。

运行库安装在项目私有目录，不替换系统库。0x804 偏移兼容仅在精确板型、
内核与 Cedar 设备上启用，其余 ioctl 原样转发。ABI 和库加载自检失败即停止。

保留 ENGINE_REQ → DMA 导入 → 显式解映射 → ENGINE_REL 的顺序。
对外给出 DMA-BUF fd、分配大小、平面偏移、步长及有效裁剪；VPU IOVA
不能直接传给 DE。借用的 fd 不由显示层关闭。显示持有数量必须反馈给
解码帧池配置，不能照搬立即 ReturnPicture 的离线解码循环。

### 显示与所有权层

仅使用厂商线性 NV12 图层，不做像素转换。区分存储高 1088 与显示高
1080，验证 UV 起点、平面大小和裁剪，并传递已协商的色彩矩阵/范围。
不确定的布局拒绝提交，不能猜测 UV 偏移。

每帧生命周期明确区分：解码完成、待提交、显示持有、可回收、已归还。
提交成功不能直接触发 ReturnPicture；fd 仍存活也不能防止 VPU 重写像素。
单一提交者管理目标图层，避免自己的并发更新破坏回收判断。

先验证厂商已有接口能否提供足够的逐帧生效/退役证据。如果不足，可以
在本项目已有 CMA 导出器上增加有界的、只读的每缓冲区导入/解映射计数或
代次观测，明确区分 VE 与 DE 附着。此信息只证明导入生命周期，不能直接
冒充呈现完成证据。不得仅凭固定 sleep 或若干 VSYNC 事件归还帧。

必须将显示寄存器生效、帧身份与回收之间的对应关系通过源码和板端观测
建立起来，才开放持续循环。若用户态与导出器无法建立该证据，停在明确
的技术阻塞点并提出最小内核改动方案；不伪造成功，也不悄悄扩大内核修改范围。

避免在没有新帧时无限重提同一 DMA-BUF：驱动每次提交会新建导入记录。
暂停输入时保持最后一帧，恢复/停止时执行有界且可验证的资源退役流程。

## 故障处理与运行约束

启动前校验板型、内核、CMA、设备、运行库、图层占用和 HDMI 模式。
不抢占已启用的测试图层；不启动另一份解码进程与测试互相干扰。
保留厂商最后关闭 `/dev/disp` 可能关闭 HDMI 的已知行为，重新启动时
只恢复已验证的输出配置，不盲目改模式。

正常停止先停止新输入和新显示提交，退役显示持有，再归还画面、销毁
解码器并解映射，最后释放设备。SIGINT/SIGTERM 走相同清理流程。
无法证明退役时明确报错，不通过强制归还或强制卸载制造悬空 DMA。

厂商 Cedar 驱动异常退出清理不可靠。SIGSEGV/SIGABRT/SIGKILL 或内核
异常后不自动重试、不强制卸载、不猜测修正全局引用计数。保存日志并
要求恢复干净内核状态。测试前将内核日志持续送回主机保存；断电会使
当前仅内存中的日志丢失，不能承诺一定捕获硬锁死最后一刻。

## 验证与完成条件

1. 建立 Linux 构建基线；新后端关闭时旧平台逻辑不变。离线测试覆盖
   格式/步长/裁剪、码流拼接、队列边界、持有/退役和异常清理状态机。
2. 固定样本在生产解码路径上逐帧校验有效 NV12 像素，不能只测独立 demo。
3. 先短时动态输出，再延长；验证实际帧身份与呈现节奏，观察无绿线、
   撕裂、错色或运行中掉信号。单独统计接收、解码、提交、确认呈现、
   丢弃、回收、队列深度、延迟与 DMA 占用。
4. 真实 Sunshine 串流以 1920×1080、60 fps 配置运行两轮至少 60 秒及
   一轮至少 10 分钟。动态内容逐帧呈现证据必须支持实际 60 fps；
   报告精确帧数、时间区间、重复/丢失与呈现间隔，不沿用旧脚本的
   “达到 58 就按 60 通过”阈值。若缺少可靠呈现证据，结果记未验证。
5. 正常停止、再次连接、输入短暂停顿与 SIGTERM 测试之后，设备引用、
   DMA 分配和显示持有均得到核对，无内核 Oops、持续增长或残留扫描。
6. 确认音频输出与键鼠输入基本功能；提供项目内构建/启动/验收入口、
   已知限制及可追溯日志。没有 Sunshine 主机或配对权限时如实记录外部
   验收阻塞，不把离线成功替换为串流成功。

所有标准针对最终生产路径，不能通过仅验证辅助探针来宣布完成。
